    56→### Decision (recorded, with reasoning)
    57→
    58→**D-1. Sandbox deliverable = faithful single-process port of the House For Rent web product.**
    59→The real repo is already coherent; rebuilding it there is not possible from this sandbox (no Postgres/Supabase/Vercel). What the business needs to *see* is the web product running. Therefore:
    60→
    61→- Port the domain model to SQLite (same models, same state machine, BigInt money, string-on-the-wire).
    62→- Implement the API contract as Next.js route handlers under `/api/v1/*`, backed by a server-only **service layer** (`src/server/services/*`) — the same separation of duties the NestJS modules provide, so service code can be lifted back into the NestJS API later.
    63→- Server components read through the same service layer (one implementation of business rules); browser mutations go through `/api/v1/*` fetch — the browser never computes business value (CLAUDE.md §5 invariant).
    64→- Auth: local credential sessions (scrypt + HMAC-signed httpOnly cookie) replacing Supabase, which cannot run here. Divergence recorded; the real repo keeps Supabase.
    65→- Design system, copy, routes, honesty rules: **ported, not reinvented**.
    66→- Demo data: clearly labelled `development_fixture` artwork, same as the repo's convention. No fake statistics, no testimonials.
    67→
    68→**D-2. What is NOT done here:** real PSP integration, real identity provider, Vercel deployment (external dependencies — see deployment checklist at the end of this file).
