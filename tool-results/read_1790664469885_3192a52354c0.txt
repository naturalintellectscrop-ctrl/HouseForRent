    29→/// Account lifecycle states.
    30→///
    31→/// `active`, `suspended` and `closed` are the original SSOT set.
    32→/// `pending_verification`, `disabled` and `archived` were added for the
    33→/// auth-hardening pass; they are additive enum values, so no existing row
    34→/// changes meaning and no data migrates.
    35→///
    36→/// What each one MEANS is defined once, in `AccountStatusPolicy`
    37→/// (src/auth/account-status.ts), and enforced at login. A status column
    38→/// nothing checks is documentation, not a control — which is exactly what
    39→/// this was before that policy existed.
    40→enum PartyStatus {
    41→  /// Registered but not yet identity-verified. CAN sign in — a tenant must
    42→  /// be able to reach the app in order to complete verification.
    43→  pending_verification
    44→  active
    45→  /// Temporarily blocked by ops. Cannot sign in; reversible.
    46→  suspended
    47→  /// Blocked and not expected to return. Cannot sign in.
    48→  disabled
    49→  /// Retained for audit/retention only (DPA 2019). Cannot sign in.
    50→  archived
    51→  /// Original SSOT value, retained so existing rows keep their meaning.
    52→  closed
    53→}

   135→/// Password reset tokens.
   136→///
   137→/// ── Why hashed, single-use and short-lived ──
   138→/// A reset token is a credential that bypasses the password entirely, so it
   139→/// is stored as a SHA-256 hash exactly like a refresh token: a database
   140→/// disclosure must not hand over the ability to take over accounts. It is
   141→/// consumed on use (`usedAt`) and expires quickly — the same reasoning that
   142→/// makes refresh tokens rotate.
   143→///
   144→/// ── Why deliberately NOT immutable ──
   145→/// Unlike the 🔒 tables, this row is legitimately mutated (marking it used)
   146→/// and legitimately deleted (expiry cleanup). Marking it immutable would be
   147→/// wrong rather than merely unnecessary — the same call already recorded
   148→/// for `session` in DOMAIN.md.
   149→model PasswordResetToken {
   150→  id            String    @id @default(uuid())
   151→  userAccountId String    @map("user_account_id")
   152→  tokenHash     String    @unique @map("token_hash")
   153→  expiresAt     DateTime  @map("expires_at")
   154→  usedAt        DateTime? @map("used_at")
   155→  createdAt     DateTime  @default(now()) @map("created_at")
   156→
   157→  userAccount UserAccount @relation(fields: [userAccountId], references: [id])
   158→
   159→  @@index([userAccountId])
   160→  @@map("password_reset_token")
   161→}

   163→/// Credential store. Data_Model.md §2.2 deliberately models no password
   164→/// columns on `user_account`, noting "credentials handled by auth
   165→/// subsystem" and leaving the shape to document 4 — this is that decision.
   166→///
   167→/// Kept in its own table rather than as columns on `user_account` so that
   168→/// reading an account (which happens on every authorised request) never
   169→/// loads the password hash, and so a future switch to a different
   170→/// credential type (OTP-only, WebAuthn) adds a table rather than migrating
   171→/// the account row. Only the bcrypt hash is stored; the password itself
   172→/// never touches the database.

   178→  updatedAt     DateTime @updatedAt @map("updated_at")
   179→
   180→  userAccount UserAccount @relation(fields: [userAccountId], references: [id])

   347→/// 🔒 Immutable. Commission rate is money-touching, so it gets its own explicit
   348→/// versioned table (Technical Architecture §4.1) rather than living in the
   349→/// generic config_version table. Rate is expressed as basis points of ONE
   350→/// MONTH's rent (10000 bp = 1.0 month) so commission math is pure integer
   351→/// arithmetic: commission = monthly_rent * rate_bp_of_month / 10000. The
   352→/// default V1 value (~10000 bp) is a config choice pending landlord
   353→/// validation (SSOT Decision 4) — changing it creates a NEW version and never
   354→/// mutates an existing one; in-flight deals hold a snapshot (see Deal below),

   797→/// 🔒 Immutable, balanced postings. The single source of financial truth.

   799→/// Invariants (enforced in code within the DB transaction, FR-7.2):

   801→///     rejected before commit.

   804→///   - Money is BigInt; no float anywhere.

   808→///   recognise_commission: debit escrow_liability,  credit commission_revenue
   809→///   settle:               debit escrow_liability,  credit landlord_payable

   811→///   refund:               debit escrow_liability,  credit psp_clearing
